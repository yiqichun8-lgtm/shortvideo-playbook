# 发布前自检

## 核心要点

> 每条作品完成后，依次检查下面七个问题。七项共同用于判断作品是否有效、
> 是否与精准粉丝相关，以及内容能否持续产生价值。
> □1 信息有效 □2 信息关联 □3 内容趣味 □4 行动成本 □5 发生频次 □6 内容持续 □7 内容价值
> 自检结果：□ 通过 □ 修改后通过 □ 暂不发布

> （成片检查三要点）结构完整、有中心思想；语言逻辑通顺、画面流畅自然；爆点前置。

## 方法说明

这是一道**质量门**，不是灵感工具。它的作用是在发布前用一个固定清单替代主观判断，
并且给出三档结论：通过 / 修改后通过 / 暂不发布——第三档是有意义的选项，
很多内容不该发出去。

七问覆盖三个层面：这条内容本身有没有价值（1、3、7）、跟我的精准用户有没有关系（2、5）、
用户能不能真的用起来（4、6）。
再叠加三条成片检查（结构完整有中心思想、语言与画面通顺、爆点前置），
以及各类型专属的自检问句。

把它作为调用收尾：任何一条脚本、任何一个标题、甚至一个已经拍好的视频，
都可以在发布前跑一遍。

## A1 — 案例

1. **同样讲减肥，两个账号差距巨大**：差别就在第二问与第四问——
   一个讲原理（行动成本高、难以尝试），一个直接讲操作。
2. **结构性回头案例**：只搜一个平台就拍的内容几乎没有流量，
   说明"信息有效"（第 1 问）的失败往往发生在素材阶段，而不是发布前。
3. **两个带货成功的案例**：
   共同点是每个环节都对应明确的可衡量目标，第三到第五问全部成立。

## A2 — 何时触发

**典型场景**
- 脚本写完、准备拍或准备发布
- 一条视频数据不好，想找原因
- 别人代写了脚本，想验收质量
- 批量预制内容时的统稿环节

**语言信号**："帮我看看这条行不行" "这条还能改吗" "为什么没人看" "验收一下脚本"
/ review my script, is this good, why no views

**与相邻能力的区分**
- 还没写脚本，想要建议怎么写 → 走四类脚本之一
- 已经过七问且确定要改某一环节 → 回到对应能力重做那一环节
- 长期数据诊断（账号级别）→ 走「进店理由与账号定位」

## E — 执行步骤

1. **跑七问**，逐项答是/否：
   ① 有用有趣有共鸣吗？② 跟精准粉丝关联度高吗？③ 不枯燥吗？
   ④ 用户容易学会吗？⑤ 是用户频繁发生的难题吗？⑥ 能持续延伸吗？⑦ 能落地解决问题吗？
   → 完成标准：七项都有明确的"是/否"，不允许"差不多"。
2. **专项验收**（按内容类型追加）：
   - 聊观点：主张能被反驳吗？每条论据落到具体的人/事/数了吗？
   - 晒过程：起因有钩子吗？经过 ≤3 且服务同一钩子吗？我是质检员还是销售员？
   - 教知识：是不是只讲了操作步骤？素材是否交叉三个来源？满足信息多/效果快/料够猛吗？
   - 讲故事：第二轮痛点/爽点高于第一轮吗？成功案例有没有写对方的努力？
   → 完成标准：所属类型的每一个问句都答了。
3. **成片三检查**：结构完整有中心思想 / 语言逻辑通顺、画面流畅自然 / 爆点是否前置。
   → 完成标准：爆点不在前三秒的，直接判定为"修改后通过"并要求重写开篇。
4. **出结论**：给出「通过 / 修改后通过 / 暂不发布」其中一档，
   并指出具体是第几问、改什么。
   → 完成标准：结论必须指向一个具体的修改动作，不能只说"再打磨一下"。

## B — 边界

- **不要用点赞数做判断标准**：正确指标是后台的**均播时长**。
  自检是对内容的判断，数据是投放后的判断，两者不可混为一谈。
- **不要为了通过七问把每条内容都做成说明书**：第三问（不枯燥）与第七问（能落地）
  常常冲突，优先保证"用户真的会用"，而不是"内容看起来完美"。
- **数据不好时不要直接归因于内容**：先回到定位层确认是否具备变现前提，
  再回到本清单——顺序反了会反复改错地方。
- **本清单不判断拍摄质量**：构图、灯光、剪辑的问题走拍摄与剪辑两张卡。
- **"暂不发布"是合法结论**：低质量内容的机会成本高于它的潜在收益，
  重做一条通常比重发更划算。
